# 阶段 2/3 实现说明（按推荐路线推进）

> 基于前一轮的 `TVBoxOS-ohos-skeleton` 继续实现。**本代码未经过 DevEco Studio 编译与 Mate 80 真机验证**，下方列出了明确的待验证点。

## 本轮新增了什么

### 阶段 2：Spider 运行时（ArkWeb + JSBridge）

| 文件 | 作用 |
|---|---|
| `entry/src/main/ets/spider/SpiderContract.ets` | 对齐 TVBox `Spider.java` 的接口契约（home/category/detail/search/play/live 等） |
| `entry/src/main/ets/spider/JsBridge.ets` | 注入 ArkWeb 的 JSAPI：`fetch`（只接受 http/https）、`log`、`getExt`；网络请求走 `@kit.NetworkKit` |
| `entry/src/main/ets/spider/SpiderRuntime.ets` | WebviewController 单例，`registerJavaScriptProxy(..., asyncMethodList:['fetch'])` 注册异步桥，`runJavaScript` 调用页面内的 Spider 适配器 |
| `entry/src/main/ets/spider/JsSpider.ets` | 把 SpiderContract 的每个方法映射到 Web 运行时中的 JS 函数 |
| `entry/src/main/resources/rawfile/spider/runner.html` | JS 运行容器：安装站点脚本、兼容 `window.VOD` 旧式 cat.js 全局函数、提供 `window.req` 兼容层 |
| `entry/src/main/ets/spider/HttpSpider.ets` | 对应配置 `type=1(json)` / `0(xml)` / `4(remote)` 的通用 HTTP JSON 采集实现 |
| `entry/src/main/ets/spider/SpiderFactory.ets` | 按 `site.type` 选择 JS 或 HTTP Spider；`type=3(jar)` 明确拒绝 DEX 并走 JS 替代 |
| `entry/src/main/ets/model/Vod.ets`, `VodParser.ets` | VOD 列表/详情模型、`vod_play_url` 首播放地址解析 |

**关键设计**：旧 TVBox JAR/JS 爬虫不是直接运行，而是要求站点脚本导出 `window.TVBoxSpider` 或沿用 `window.VOD` 的 `home/category/detail/search/play` 全局函数。`runner.html` 提供映射层；新站点建议直接实现 `window.TVBoxSpider`。

### 阶段 3：播放器（AVPlayer）

| 文件 | 作用 |
|---|---|
| `entry/src/main/ets/player/PlayerEngine.ets` | `media.createAVPlayer()`，XComponent surface、URL/带 Header 的 `media.createMediaSourceWithUrl`、`prepare/play/pause/seek/setSpeed/release`、时间与错误回调 |
| `entry/src/main/ets/pages/Player.ets` | XComponent 渲染 + 播放/暂停/倍速/进度条/返回 |
| `entry/src/main/ets/pages/Home.ets` | 站点切换、首页/分类/搜索、详情解析首播地址并跳转播放器；挂载隐藏 Web 作为 JS Spider 运行时 |

首页流程：配置导入（阶段 1）→ 进入首页 → 选站点 → 加载首页/分类/搜索 → 点片 → `detailContent` → `vod_play_url` 解析 → 播放页。

## 编译前必须核对的 API 点（未验证清单）

1. `webview.WebviewController.registerJavaScriptProxy(jsObject, name, methodList, asyncMethodList)`：异步方法 `fetch` 是否按 Promise 暴露；`onControllerAttached` 中注册后是否还需 `refresh()`。
2. `controller.runJavaScript(script, callback)` 的 callback 签名与返回类型；本实现假定第二参数为执行结果字符串，并用 IIFE + `JSON.stringify` 包装。
3. `AVPlayer.setDisplaySurface(surfaceId)`：部分 SDK 版本签名带 callback，需按 IDE 提示补第二参数；必须在 `prepare()` 之前调用。
4. `AVPlayer.setMediaSource(source)`：流式播放文档中出现 `setMediaSource(source, playbackStrategy)` 形式，需确认第二参数是否可选；若是必填，按业务填写播放策略。
5. `XComponentController.getXComponentSurfaceId()` 与 `XComponent({ type: 'surface' })` 的配套用法。
6. `router.getParams()` 返回 `Object` 的断言方式，以及 `Slider` 的 `max` 绑定在 `duration=0` 时的边界。
7. `build-profile.json5` 的 `26.0.0` 与 `oh-package.json5` 的 hvigor `5.0.0`：以本机 HarmonyOS 7 / DevEco Studio 26 模板实际值为准。

## 已知降级

- `type=3(jar)` 的爬虫无法在鸿蒙运行，工厂返回 HTTP Spider 兜底；实际项目需把 JAR 源转 JS 或服务端代理。
- Python（pyramid/Chaquopy）爬虫未迁移。
- DLNA（Cling + nanohttpd）未迁移；一期不提供投屏。
